# 性能测量

`scripts/measure-performance.py` 启动隔离的临时部署，测量真实 HTTP 调用。
使用 instant 节奏、128 字符预设和本机模拟上游，并开启 SQLite WAL/FULL
计数与四字段请求日志。服务、Key、模拟上游的容量临时提高到 128；
并发数为客户端同时请求数，不代表默认配置支持的并发或用户数量。

每个场景先预热 5 次，再测量 256 次。JSON 和 SSE 都读到响应结束，
同时验证正文、流终止、总/AI 扣次数，以及模拟上游实际调用数。
Python 客户端使用独立 HTTP 连接；结果包含客户端调度、连接、磁盘提交和日志成本。

## 本机 Windows 观察

2026-10-12，Windows 11 amd64、24 个逻辑 CPU、Go 1.27.2、Python 3.13.11，
本机 loopback，精简二进制约 12.8 MiB。

| 场景 | 并发请求 | 请求/秒 | p50 / p95 毫秒 |
|---|---:|---:|---:|
| 128 字符预设 JSON | 1 | 105.91 | 4.09 / 29.04 |
| 128 字符预设 JSON | 16 | 324.30 | 43.04 / 98.95 |
| 128 字符预设 JSON | 64 | 321.37 | 150.91 / 418.00 |
| 128 字符预设 SSE | 64 | 316.92 | 146.25 / 377.91 |
| 本机模拟上游 JSON | 64 | 321.23 | 139.34 / 379.48 |
| 完整挥手字符画 SSE | 4 | 253.49 | 12.07 / 32.70 |

启动到 readyz 成功的三次观察为 579 / 571 / 556 毫秒，其中后两次为重启。
空闲 RSS 约 17.5 MiB；测量期间每 250 毫秒采样的最大 RSS 约 41.2 MiB。
这只是采样最大值，不是进程所有瞬间的峰值。

约 8 MiB、超过配置请求体上限的请求返回 413，不扣额度；其客户端往返约 69 毫秒。
取消慢速 SSE 后，用单并发 Key 发起新请求成功约需 5.7 毫秒；已接收的取消请求仍计数。
完整场景共验证 2,871 次负载调用及 783 次模拟上游调用，另外验证取消/恢复的两次扣减。

## GitHub Linux 观察

[预发布验收运行](https://github.com/CyrusAuyeung/FakeAPI/actions/runs/38271953449)
的 Ubuntu 24.04 x86_64 runner 有 4 个逻辑 CPU，使用相同的 256 次样本与测试配置。

| 场景 | 并发请求 | 请求/秒 | p50 / p95 毫秒 |
|---|---:|---:|---:|
| 128 字符预设 JSON | 64 | 1268.16 | 25.80 / 69.89 |
| 128 字符预设 SSE | 64 | 1119.62 | 31.57 / 79.88 |
| 本机模拟上游 JSON | 64 | 824.84 | 69.23 / 77.01 |

三次启动观察约 22 / 21 / 21 毫秒，空闲 RSS 约 21.6 MiB，
采样最大 RSS 约 38.8 MiB，取消后新请求完成约 1.7 毫秒。
完整 JSON 在运行的 `runtime-Linux-X64` artifact 中。
这是主机测试，不能当作 2 vCPU / 1 GiB 容器的测量。

## 重现及边界

```text
python scripts/measure-performance.py --samples 256
python scripts/measure-performance.py --binary PATH --report PATH
```

JSON 报告默认保存到 `.cache/acceptance/performance-<system>-<architecture>.json`。
GitHub Actions 在 Linux 也执行该脚本并上传报告。测量不联系真实 AI，
不记录 Key、正文、机器用户名或环境变量。

这些是特定机器和短时样本的观察，不是固定性能保证。自然/调皮节奏、远程网络、
真实 AI 和不同磁盘会改变结果。参考的 2 vCPU / 1 GiB 容器、最大合法响应、
持续负载与容器镜像大小仍需单独测量；不以主机测量代替这些结果。
CI 只对响应正确、计数和清理作断言，不以固定吞吐或延迟阈值阻止发布。
